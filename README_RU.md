# Search Adaptive Chrome v0.3

**Для macOS / Search Browser.** Это небольшой модуль для изменения *нативной* панели Search, а не расширение из магазина. Установленный оригинальный Search не меняется: создаётся отдельная копия `~/Applications/Search Adaptive.app`.

## Что нового в v0.3

1. **Быстрые, но плавные изменения цвета.** При смене темы сайта или CSS-фона цвета панели и вкладок меняются с плавным переходом примерно за 240 мс. На переход между разными вкладками не навязывается лишняя анимация расположения кнопок.
2. **Поиск поверх сайта больше не выбеливает тёмные страницы.** Вместо белого цвета, взятого из настроек Search, подложка поиска выбирает светлое/тёмное затемнение по реальному фону активной страницы. **Верхняя панель и вертикальные вкладки получают такую же подложку** и плавно возвращаются назад при закрытии поиска. Цвет поля ввода и списка подсказок также подстраивается под страницу, а в нативном AppKit-поле меняется цвет текста и placeholder.
3. **HSL вместо серого смешивания.** Активная вкладка, hover, закреплённые вкладки и кнопки отличаются светлотой, но сохраняют оттенок исходного фона. Это особенно заметно на тёмных синих/зелёных сайтах. Основной фон панели при этом **не корректируется по HSL**: он стремится совпадать с реальным цветом страницы.
4. **Уточнение цвета по пикселям.** После CSS-анализа небольшой полоски у верхнего края WebView допускается ограниченное по частоте сравнение с реальной отрисовкой. Оно помогает устранить небольшие расхождения оттенка. Максимум четыре снимка на документ; каждый запрашивается только при изменении цвета, без модального затемнения.
5. **Меньше вспышек при переходах.** При загрузке нового URL предыдущий цвет кратковременно сохраняется, пока не придёт цвет следующего документа. Если страница не ответит, обычное оформление вернётся.
6. **Обновления по-прежнему одной командой.** Патчер изменяет шесть файлов штатного Search: `Tab.swift`, `App.swift`, `Side.swift`, `TabBar.swift`, `Omnibox.swift`, `Updater.swift`; остальное находится в отдельном `AdaptiveChrome.swift`.

**Статус:** экспериментальная v0.3. Проверены JS-детектор, Python-патчер, shell-скрипт, синтаксис Swift. Реальная компиляция и визуальная проверка macOS в данной среде недоступны — приложение нужно собрать на своём Mac.

## Установка / обновление поверх v0.2

1. Закрой Search и Search Adaptive. На всякий случай сохрани резервную копию `~/Library/Application Support/Search` (данные профиля браузера).
2. Распакуй `search-adaptive-kit-v0.3.zip` в отдельную папку. Старые файлы v0.2 не смешивай с v0.3.
3. Перейди в папку с новым комплектом и запусти:

```bash
cd "$HOME/Downloads/search-adaptive-kit"
./update-and-build.sh
```

4. После установки:

```bash
./toggle-mode.command on
open "$HOME/Applications/Search Adaptive.app"
```

Никаких дополнительных настроек для плавного перехода и подложки поиска не требуется. Если ты менял исходники вручную, скрипт восстановит актуальный `main` Search **только** в своём выделенном рабочем клоне, затем применит весь комплект v0.3.

## Обновления после v0.3

Закрой браузер и снова выполни `./update-and-build.sh` из **этой** папки. Скрипт скачает последний `main` Search, сбросит изменения **только в выделенном клоне**, применит модуль, соберёт и заменит `Search Adaptive.app` с резервной копией. Если сборка не прошла, ранее установленное приложение сохранится.

Официальный автообновлятор Search специально заблокирован только внутри этой модифицированной сборки. В обычном Search он работает как прежде.

## Диагностика и управление

```bash
./toggle-mode.command status
./toggle-mode.command debug-on
./toggle-mode.command debug-off
./toggle-mode.command off
```

Перезапускай Search Adaptive после изменения настроек. При `debug-on` в нижней части верхней панели отображается источник/цвет/затемнение — можно сделать скрин проблемного сайта. В вертикальном сайдбаре диагностическая подпись намеренно не рисуется. Важно: диагностика читает только цвет и визуальный CSS, никаких данных сайтов во внешние сервисы не отправляет.

## Что проверить визуально

- **QDET / Администрирование:** верхний фон должен быть близок к тёмной странице, а не ярко-бирюзовым. Отдельные кнопки цвета морской волны не должны влиять на всю панель.
- **QDET / Проекты:** активная вкладка и hover должны сохранить оттенок базового фона, а не превращаться в обычные нейтрально-серые плашки.
- **QDET / О технологии:** при открытии светлого модального окна подложка должна затемнять и браузерную панель. При закрытии — возвращаться к прежнему виду.
- **Новая вкладка / закрытие:** верхние кнопки не должны «падать сверху». Анимации самих вкладок могут остаться.
- **Смена светлой/тёмной темы:** текст и кнопки должны оставаться читаемыми.

## Устранение проблем

**`SwiftUIMacros.StateMacro not found`**: обычно `swift` взят из Command Line Tools вместо полноценного Xcode. Установи Xcode из App Store и открой его один раз; скрипт сам выберет `Xcode.app/Contents/Developer`. Чтобы вручную выбрать его на один вызов:

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer ./update-and-build.sh
```

**`Search Adaptive: upstream changed; stopped safely`**: разработчик Search изменил структуры, на которые опираются наши шесть точек интеграции. Патчер не должен слепо править изменённый код; нужен обновлённый патч.

**Компилятор сообщает другую ошибку**: смотри самый первый `error:` в сохранённом файле `~/Library/Application Support/SearchAdaptive/last-build.log`. Весь лог прикладывать необязательно; нужны первые ошибки, относящиеся к `AdaptiveChrome.swift` или указанному исходнику.

**После сборки виден старый результат**: закрой Search и Search Adaptive, проверь, что запускаешь `~/Applications/Search Adaptive.app`, а не официальный `Search.app`. Включение режима сохраняется в `defaults` и требует перезапуска.

## Для разработчика

- `AdaptiveChrome.swift`: изолированный WebKit JS detector + bounded snapshot fallback + палитра + устойчивые SwiftUI modifier и диагностическая подпись.
- `apply_mod.py`: идемпотентный патч 6 файлов: `Tab.swift`, `App.swift`, `Side.swift`, `TabBar.swift`, `Omnibox.swift`, `Updater.swift`. При несовпадении якорей прерывается без частичной записи.
- `update-and-build.sh`: Xcode, Git, patch, production build, staged install.
- `toggle-mode.command`: включение/выключение и диагностика.
- `tests/color-detector.test.js`: тесты выборки фона, яркого акцента, модального затемнения и градиентного fallback (опционально требуется Node.js).
- `tests/patcher.test.py`: идемпотентность патча и остановка без частичной записи при несовпадении якорей.

```bash
python3 tests/patcher.test.py
node tests/color-detector.test.js
```

### Известные ограничения

Цвет извлекается эвристически. Видео-шапки, canvas, сложные SVG/градиенты, Shadow DOM, прозрачные слои, нестандартные `backdrop-filter` и собственные системы модальных окон могут давать отличия. Для нескольких независимых панелей Split View пока берётся цвет активной вкладки, а не каждого разделённого участка. `WKSnapshot` включается редко, чтобы не влиять заметно на скорость. Нативные macOS traffic lights не перекрашиваются модулем, а цветовое затемнение модального окна определяется приближённо.
