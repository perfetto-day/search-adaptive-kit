# Search Adaptive Chrome v0.5

**Для macOS / Search Browser.** Это небольшой модуль для изменения *нативной* панели Search, а не расширение из магазина. Установленный оригинальный Search не меняется: создаётся отдельная копия `~/Applications/Search Adaptive.app`.

## Что нового в v0.5

1. **Поиск на тёмных страницах:** поиск, фон верхней панели и боковая панель теперь подписываются на **одну общую модель цвета окна**, поэтому при открытии новой вкладки не должно быть ситуации «тёмный tabbar, белое поле поиска». В самом компоненте `Omnibox` цвет берётся напрямую из модели, а не только из SwiftUI `Environment`.
2. **Цвет страницы и модальных окон:** используется реальный RGB и прозрачность подложки, если сайт предоставляет их через CSS; для нестандартных оверлеев остаются эвристические ограничения.
3. **Скругление страницы:** под горизонтальным tabbar у **самого WKWebView** скругляются только верхние два угла, радиусом `Metrics.cardRadius` (10 pt). Существующее скругление страниц-карточек не меняется. Для Split View пока без дополнительного скругления.
4. **Проверка официальных обновлений:** включена **по умолчанию**, как в Search. При обнаружении нового официального релиза появляется сообщение в самом приложении; **автоматическая установка официального бинарника заблокирована**, чтобы не потерять патч. После уведомления обновляй через `./update-and-build.sh`. Это проверка релизов Search, не каждого коммита в GitHub `main`.
5. **Выключаемые проверки:** `./toggle-mode.command updates-off` / `updates-on`. Ручная проверка через меню Search остаётся доступна. Перезапусти приложение после переключения. Настройка использует UserDefaults `adaptive.chrome.updateChecks`, если ключ не задан — `true`.
6. **Сохранена совместимость обновлений:** патчер меняет семь исходных файлов Search: `Tab.swift`, `App.swift`, `Side.swift`, `TabBar.swift`, `Omnibox.swift`, `Updater.swift` и `Stage.swift`. Алгоритм определения цвета находится в отдельном `AdaptiveChrome.swift`.

**Статус:** экспериментальная v0.5. Пройдены тесты JS-детектора, Python-патчера, shell и синтаксиса Swift. Полная сборка Xcode и проверка UI на Mac остаются необходимыми.

## Установка из GitHub (ветка PR #2)

1. Закрой Search и Search Adaptive. На всякий случай сделай резервную копию `~/Library/Application Support/Search` (профиль браузера).
2. Если репозиторий ещё не клонирован, открой Terminal и выполни:

```bash
cd ~/Downloads
git clone https://github.com/perfetto-day/search-adaptive-kit.git
cd search-adaptive-kit
git switch fix/v0.4-omnibox-modal-color
```

3. Если уже клонирован — обнови существующую ветку:

```bash
cd ~/Downloads/search-adaptive-kit
git fetch origin
git switch fix/v0.4-omnibox-modal-color
git pull --ff-only
```

4. Собери и установи отдельный браузер:

```bash
./update-and-build.sh
./toggle-mode.command on
open "$HOME/Applications/Search Adaptive.app"
```

Версия v0.5 сейчас находится в рабочей ветке PR #2. После слияния в `main` переключение на неё перестанет быть необходимым. Скрипт сбрасывает **только** свой выделенный клон Search, не оригинальный браузер и не этот репозиторий.

## Обновления после v0.5

Закрой браузер и снова выполни `./update-and-build.sh` из **этой** папки. Скрипт скачает последний `main` Search, сбросит изменения **только в выделенном клоне**, применит модуль, соберёт и заменит `Search Adaptive.app` с резервной копией. Если сборка не прошла, ранее установленное приложение сохранится.

Проверка новых официальных релизов теперь включена; автоматическая установка официального бинарника в модифицированную сборку запрещена. При появлении обновления приложение сообщит об этом. Сама сборка обновляется через этот скрипт. В обычном Search поведение не меняется.

## Диагностика и управление

```bash
./toggle-mode.command status
./toggle-mode.command updates-on   # по умолчанию включено
./toggle-mode.command updates-off  # запрет фоновых проверок
./toggle-mode.command debug-on
./toggle-mode.command debug-off
./toggle-mode.command off
```

Перезапускай Search Adaptive после изменения настроек. При `debug-on` в нижней части верхней панели отображается источник/цвет/затемнение — можно сделать скрин проблемного сайта. В вертикальном сайдбаре диагностическая подпись намеренно не рисуется. Важно: диагностика читает только цвет и визуальный CSS, никаких данных сайтов во внешние сервисы не отправляет.

## Что проверить визуально

- **Тёмная страница с ярким акцентом:** верхний фон должен быть близок к тёмной странице, а не ярко-бирюзовым. Отдельные кнопки цвета морской волны не должны влиять на всю панель.
- **Тёмная страница и вкладки:** активная вкладка и hover должны сохранить оттенок базового фона, а не превращаться в обычные нейтрально-серые плашки.
- **Модальное окно со светлым содержимым:** при открытии светлого модального окна подложка должна затемнять и браузерную панель. При закрытии — возвращаться к прежнему виду.
- **Новая вкладка / закрытие:** верхние кнопки не должны «падать сверху». Анимации самих вкладок могут остаться.
- **Смена светлой/тёмной темы:** текст и кнопки должны оставаться читаемыми.

## Устранение проблем

**`SwiftUIMacros.StateMacro not found`**: обычно `swift` взят из Command Line Tools вместо полноценного Xcode. Установи Xcode из App Store и открой его один раз; скрипт сам выберет `Xcode.app/Contents/Developer`. Чтобы вручную выбрать его на один вызов:

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer ./update-and-build.sh
```

**`Search Adaptive: upstream changed; stopped safely`**: разработчик Search изменил структуры, на которые опираются наши семь точек интеграции. Патчер не должен слепо править изменённый код; нужен обновлённый патч.

**Компилятор сообщает другую ошибку**: смотри самый первый `error:` в сохранённом файле `~/Library/Application Support/SearchAdaptive/last-build.log`. Весь лог прикладывать необязательно; нужны первые ошибки, относящиеся к `AdaptiveChrome.swift` или указанному исходнику.

**После сборки виден старый результат**: закрой Search и Search Adaptive, проверь, что запускаешь `~/Applications/Search Adaptive.app`, а не официальный `Search.app`. Включение режима сохраняется в `defaults` и требует перезапуска.

## Для разработчика

- `AdaptiveChrome.swift`: изолированный WebKit JS detector + bounded snapshot fallback + палитра + устойчивые SwiftUI modifier и диагностическая подпись.
- `apply_mod.py`: идемпотентный патч 7 файлов: `Tab.swift`, `App.swift`, `Side.swift`, `TabBar.swift`, `Omnibox.swift`, `Updater.swift`, `Stage.swift`. При несовпадении якорей прерывается без частичной записи.
- `update-and-build.sh`: Xcode, Git, patch, production build, staged install.
- `toggle-mode.command`: включение/выключение цветов, диагностика и управление проверкой обновлений.
- `tests/color-detector.test.js`: тесты выборки фона, яркого акцента, модального затемнения и градиентного fallback (опционально требуется Node.js).
- `tests/patcher.test.py`: идемпотентность патча и остановка без частичной записи при несовпадении якорей.

```bash
python3 tests/patcher.test.py
node tests/color-detector.test.js
```

### Известные ограничения

Цвет извлекается эвристически. Видео-шапки, canvas, сложные SVG/градиенты, Shadow DOM, прозрачные слои, нестандартные `backdrop-filter` и собственные системы модальных окон могут давать отличия. Для нескольких независимых панелей Split View пока берётся цвет активной вкладки, а не каждого разделённого участка. `WKSnapshot` включается редко, чтобы не влиять заметно на скорость. Нативные macOS traffic lights не перекрашиваются модулем, а цветовое затемнение модального окна определяется приближённо.
